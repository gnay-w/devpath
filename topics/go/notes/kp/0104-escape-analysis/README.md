## 正文

### 一句话

**逃逸分析** = 编译器判断变量生命周期是否可能超出当前栈帧。  
不超出 → 可放栈；超出 → **逃逸到堆**，由 GC 回收。

因此 `return &局部` 在 Go 里**合法且安全**：不是悬空指针，而是变量被放到堆上了。

### 和 Java 差在哪

| | Java | Go |
|---|---|---|
| 默认分配 | 对象几乎都在堆 | **尽量栈**；逃逸才上堆 |
| 返回局部 | 对象本就在堆，返回引用自然 | 看起来像「返回栈地址」，编译器已处理逃逸 |
| 你要记的 | 堆是常态 | 栈是默认优化；先保证语义，再用 `-m` 看成本 |

### 试探题 1

```go
func f() (*int, int) {
    x := 1
    p := &x
    return p, x
}
```

- 返回的 `p`：安全 —— `&x` 逃出函数，`x` **moved to heap**。  
- 返回的 `x`：安全 —— **值拷贝**，与栈/堆无关。

### 返回值 vs 返回指针

```go
func A() User  { u := User{Name: "a"}; return u }   // 值拷贝，地址没出去
func B() *User { u := User{Name: "b"}; return &u }  // 返回地址 → u 逃逸
```

`-gcflags='-m -l'` 下通常只有 `B` 出现 `moved to heap: u`。

### 「返回的是值」仍可能逃逸：`any`

`any` ≡ `interface{}`（空接口，像粗对应 Java `Object`）。

返回 `any` 时，拷出去的是**接口头（值）**，但头里常带着**指向真实数据的指针**。若数据还在栈上，返回后会悬空，所以内容常上堆：

```text
D() int：纯位模式拷贝 → 不必回指栈
C() any：盒子 ≈ {类型, data:──►42} → 42 常 escapes to heap
```

规则统一：**拷出去的东西只要还「指着」函数里的数据，那份数据就要逃逸（或被拷到堆）。**  
`*T`、`any` 都属这类；纯 `int`/`User` 值拷贝则不是。

### 怎么看编译器提示

```bash
go build -gcflags=-m .
# 少看内联噪音：
go build -gcflags='-m -l' .
```

| 字样 | 含义 |
|------|------|
| `moved to heap: x` | 局部变量 `x` 放到堆上（本课主盯） |
| `... escapes to heap` | 某值逃逸（常见于装进 interface） |

语义对错 ≠ 分配在哪；`-m` 只帮看成本。
