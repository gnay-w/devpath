# 0110 struct 与 method

## 目标

能说明何时用指针接收者；对应 curriculum 验收。

## 写本篇时的基础假设

- 0102 / 0103 已会：struct 零值；传值拷贝 vs 传指针共享。  
- 缺口：接收者选择可能随意；易按 Java「方法总改同一对象」硬套。

## 正文

### 一句话

Go **没有 class**。数据用 `struct`，行为用带接收者的 method。接收者是值还是指针，语义等于 0103 的传参规则。

### 对照 Java

| Java | Go |
|------|-----|
| `class` 装字段 + 方法 | `type T struct` + `func (t T|/ *T) ...` |
| 实例方法几乎总改同一对象 | 值接收者改的是 **拷贝** |
| `this` 隐式 | 接收者要自己命名 |

### 值 vs 指针接收者

```text
(c Counter)  IncValue  → 改拷贝，外面不变
(c *Counter) IncPtr    → 共享原件，外面变
```

教学小测：`IncValue` 再 `IncPtr` → `N` 从 0 到 **1**（用户已答对）。

### 何时用指针接收者

| 场景 | 倾向 |
|------|------|
| 要改接收者状态 | `*T` |
| struct 较大，不想每次拷贝 | `*T` |
| 只读、小结构体 | `T` 也可 |
| 同一类型有改状态的方法 | 通常统一 `*T` |

验收口述（用户）：需要改 / 对象大 → 指针；只读 → 值；值接收者不会改本对象。

### 调用语法糖

- 值变量调指针方法 → 编译器加 `&`（须可取址）  
- 指针调值方法 → 编译器解引用  
- `Counter{}.IncPtr()` 临时值不可取址 → 编译失败  

### 方法集（预埋 0112）

| 类型 | 方法集 |
|------|--------|
| `T` | 仅值接收者方法 |
| `*T` | 值 + 指针接收者方法 |

变量上调用常有糖；塞进 interface 时方法集会咬人 → **0112**。

### 构造习惯

无构造器语法；`NewXxx` 返回 `T` 或 `*T`。后面要改状态时，常直接返回 `*T`。

### 与前置 / 引出

- **0102 / 0103：** 零值与值/指针传参 → 直接映射到接收者。  
- **0111：** 嵌入与组合。  
- **0112：** interface 与方法集。

## 最小例子

```go
u := User{Name: "Alice"}
u.RenameVal("Bob")  // 仍 Alice
u.RenamePtr("Bob")  // 变 Bob
```

## 验收题（已通过）

1. 要改状态或避免大拷贝 → 指针接收者；只读可用值接收者。  
2. 值接收者不会改本对象（与 Java 实例方法默认语义不同）。
