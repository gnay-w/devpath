## 正文

### 一句话

类型**不用**声明 `implements`。只要方法集覆盖接口要求的方法，就算满足——编译期核对，不是运行时鸭子。

### 对照 Java

| Java | Go |
|------|-----|
| `class X implements Writer` | 无对应语法 |
| 大接口 + 显式实现常见 | **小接口**更常见；可再组合 |
| 类上声明关系 | 靠方法集自动对齐 |

### 隐式满足

```go
type Writer interface {
	Write([]byte) (int, error)
}
type Buffer struct{}
func (b Buffer) Write(p []byte) (int, error) { return len(p), nil }

save(Buffer{}) // OK：方法凑齐即可
```

### 方法集（进 interface 时无糖）

| | 值接收者方法 `(T)` | 指针接收者方法 `(*T)` |
|--|-------------------|------------------------|
| 类型 `T` | 有 | **没有** |
| 类型 `*T` | 有 | 有 |

- **变量上调用**常有糖：`x.PtrMethod()` ≈ `(&x).PtrMethod()`（须可取址）。  
- **塞进 interface** 无糖：只认方法集。指针方法 ⇒ 通常传 `&x` / `*T`。

教学澄清（用户原理解）：「值/指针都能调」主要是调用糖；实现接口看方法集，两者不是一回事。

### 为何指针方法不算进 `T`

Interface 盒子里是已装好的 (type, value)。若允许值进盒子却调指针方法，指针只能指到**盒子里的副本**，改不到外面——又像能改又改不到。语言直接禁止，逼你塞 `*T`。

### 小接口习惯

用得到哪里就定义小接口（1～3 方法常见），再组合；不必先造大 `Service`。标准库 `io.Writer` 即此风格。

教学验收口述（用户）：方法碰得上就行；接口可以很小，再组合起来。
