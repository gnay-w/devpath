# 0111 嵌入与组合

## 目标

能写清嵌入提升与名字冲突时的选择；对应 curriculum 验收。

## 写本篇时的基础假设

- 0110 已会：struct + method；值/指针接收者。  
- 缺口：Java 继承习惯需刻意换成组合；嵌入 ≠ extends。

## 正文

### 一句话

嵌入是组合的**懒写法**：字段只写类型、不写名字。不撞名时，嵌进去的字段/方法可以**少写一层**；语义仍是「有一个」，不是继承。

### 对照 Java

| Java | Go |
|------|-----|
| `Car has Engine` 字段 | 具名字段 `Engine Engine`，或嵌入 `Engine` |
| `class Car extends Engine` | **没有**对应物；嵌入不产生父子类型 |
| 子类方法覆盖父类 | 外层同名方法优先（像覆盖，但是组合） |

### 普通组合 vs 嵌入

```text
CarA { Engine Engine }  →  a.Engine.Start()
CarB { Engine }         →  b.Start() 也行（提升）
                          b.Engine.Start() 仍可用
```

### 提升

嵌入的字段/方法，在**名字不重复**时，可当成外层的来写（少一层）。

### 名字冲突时的选择

| 情况 | 行为 |
|------|------|
| 外层自己有同名 | 用外层；嵌进去的写全路径 |
| 多个嵌入同名、外层没有 | 必须写全路径（ambiguous，不能 `c.Start()`） |

教学小测：`Dog` 嵌 `Animal`，外层自有 `Speak` → `p.Speak()` 打印 **woof**（用户已答对）。

### 何时用嵌入

| 场景 | 建议 |
|------|------|
| 「有一个」，且常透传字段/方法 | 可嵌入 |
| 偶尔用内部类型 | 具名字段更清晰 |
| 多嵌入易撞名 | 慎用 / 具名 |
| 想像「是一种」继承 | 别；Go 没有这层类型关系 |

### 教学澄清

- 「提升」≠「外层优先」。提升 = 不撞名时少写一层；外层优先 = 撞名时用外层。  
- 用户口述验收：不重复时可简写一层；多同名须写全路径。

### 与前置 / 引出

- **0110：** struct + method → 嵌入提升的是字段与方法。  
- **0112：** interface 隐式满足（嵌入也会把方法带进方法集）。

## 最小例子

```go
type Car struct {
	Engine // 嵌入
	Brand  string
}
c.Start()  // ≡ c.Engine.Start()，不撞名时
c.Power    // ≡ c.Engine.Power
```
